# P02 콘텐츠 기준과 검증

콘텐츠 원본은 [Catalog](../content/catalog.json), 도착 시연 입력은 [scenarios](../fixtures/scenarios.json), 화면 예시는 [UI samples](../fixtures/ui_samples.json)다. 이 문서는 2026-11-03 P02 작업에서 현재 기준을 정리하며 새 승인 절차를 만들지 않는다.

## 유지하는 콘텐츠

- 캐릭터 3종: 토리(tori), 모모(momo), 루루(lulu).
- 지역 3곳·아이템 9개, 각 지역은 FOOD·OUTFIT·DECOR 각 1개다.
- DAILY 성장 0~3단계, 하루 1회, Asia/Seoul 기준. 장식 슬롯은 3개다.
- contentVersion 1.1.0, 기존 ID·assetKey·슬롯 ID·저장 스키마·보상 규칙을 유지한다.

| 지역 | 음식 | 의상 | 장식 |
|---|---|---|---|
| 대전 | 빵 | 빵모자 | 작은 빵 간판 |
| 원주 | 감자 음식 | 은행잎 머리장식 | 은행나무 |
| 속초 | 회 접시 | 파도 목도리 | 바다 조개 |

지역 소재는 게임 테마다. 공식 특산품 인증·매장 제휴·특정 점포 방문 인증을 뜻하지 않는다. 좌표는 시연용 앵커이며 새 지오펜싱이나 위치 인증을 추가하지 않는다.

## 그래픽 A안 연결

B의 오프라인 3D → PNG 제작 방향을 유지한다. PM은 Catalog와 데이터 참조를 맡으며 3D 모델·캐릭터 렌더러·B 자산을 대신 제작하지 않는다. C와 P01은 기존 AvatarPreview/주입 슬롯 등 연결 계약을 유지한다.

현재 Catalog 이미지 경로는 assets/starter 바로 아래의 .png 파일이다. 공통 빌드의 루트 PNG 복사와 CatalogAssets의 assets/starter 경로 읽기를 함께 만족해야 한다. 파일이 저장소에 존재한다는 이유만으로 README·다른 폴더·하위 폴더 이미지를 정상 자산으로 통과시키지 않는다. 배포 경로를 바꿀 경우 A의 패키징과 소비자 연결까지 함께 바뀌어야 하며, 이번 P02는 그 경계를 변경하지 않는다.

기존 경로의 원본 도형은 유효한 임시 자산이다. 최종 아트 제작·미적 승인·실제 APK의 레이어 정렬은 완료로 표시하지 않는다. 새 이미지 사용 시 B가 실제 출처에 맞춰 [자산 표기](../assets/ATTRIBUTION.md)를 갱신한다.

## 검증 범위

python3 scripts/check_all.py가 콘텐츠·시연·UI 샘플과 패키지를 검사한다. 고정 MVP 개수·성장 상한·슬롯 수, 비어 있는 이름/지역 테마, APK에 포함되지 않는 이미지 경로를 거부한다. REGION 샘플이 DAILY 성장까지 기대하거나 DAILY 화면 영수증이 한 번에 2단계 성장하는 입력도 거부한다.

이 검증은 JSON 입력·표시 예제의 정합성 검사다. 실제 지급·원자 저장·중복 방지·기기 UI·차량 제한 동작을 대신 시험하지 않는다. B의 실제 GameService와 A의 연결은 각 담당 기능 및 P03에서 검증한다.
