# PM Mac 검토 결과 ZIP 저장 규칙

이 규칙은 PM의 로컬 Mac에서 Codex·Claude가 수행한 MEMORIDE 작업의 검토 결과에 적용한다. 파트·기능·계약·개발 노력 배분은 변경하지 않는다.

## 저장 위치와 시점

- 검토가 필요한 작업을 마칠 때 관련 결과물과 보고서를 ZIP 하나로 묶는다. 읽기 전용 점검도 보고서가 있으면 해당한다.
- PM Mac의 저장 위치는 현재 사용자의 `~/Downloads/`다. 홈 디렉터리를 실제 실행 계정에서 해석하고 저장한다.
- 파일명 예시는 `MEMORIDE_PM_<작업ID>_20261102_142000_KST.zip`이다. 실제 완료 시각을 KST로 넣고 같은 이름이 있으면 덮어쓰지 말고 번호를 붙인다.
- 실제 Mac에서 저장한다. Linux·원격 컨테이너에서 Mac의 홈 경로를 임의로 만들어 Mac에 저장했다고 보고하지 않는다.
- Windows 팀원은 이 Mac 경로를 사용하지 않는다. 검토 ZIP이 필요하면 본인의 실제 Downloads 또는 지정 폴더를 사용한다.

## ZIP에 넣을 것

1. `REPORT.md`: 작업 목적·담당·실제 OS/CPU·브랜치·시작/종료 SHA·변경 내용·실행 명령과 종료 코드·PASS/FAIL/NOT RUN/BLOCKED·남은 문제·다음 작업.
2. 필요한 최소 로그: 실패 원인이나 실제 성공을 확인하는 구간만 포함한다. 환경 변수 전체나 인증 정보는 넣지 않는다.
3. 코드·문서가 바뀌었다면 작업 범위를 확인할 패치 또는 필요한 변경 파일을 포함한다. 커밋된 변경과 아직 커밋되지 않은 변경을 구분하고, diff에 잡히지 않는 새 파일도 빠뜨리지 않는다.
4. 요청된 결과물이나 재현용 샘플이 있으면 관련 파일만 포함한다. 변경이 없는 진단이면 보고서만으로 충분하다.

이 항목을 위해 별도의 장문 보고 체계를 만들지 않는다. 간단한 작업은 짧은 보고서 하나면 된다. 현재 작업과 무관한 파일을 모으지 않는다.

## 제외할 것

저장소 전체·사용자 홈·Downloads 전체를 통째로 압축하지 않는다. `.git`, 캐시, `.gradle`, `.idea`, 가상환경, node_modules, 일반 build 출력은 제외한다. APK는 요청된 시연 결과일 때만 필요한 파일을 넣는다.

서명키·keystore·토큰·API 키·`.env`·인증 파일·서명된 개인정보 양식은 넣지 않는다. 임시 로그의 민감한 값도 제거한다. 저장소 원격 URL에 자격 증명이 섞여 있으면 출력하거나 그대로 패키징하지 않는다.

## 생성과 확인

Python 표준 라이브러리 `zipfile`로 생성할 수 있다. 새 유료 서비스·압축 패키지·Actions를 추가하지 않는다. 임시 파일로 만든 뒤 ZIP 읽기와 무결성을 확인하고 최종 이름으로 옮기는 방식이 가능하다.

최종 파일이 실제 존재하며 크기가 0보다 큰지, 압축 목록이 예상한 파일만 담는지, `ZipFile.testzip()`이 오류를 반환하지 않는지 확인한다. 저장 권한이나 로컬 폴더 접근이 막히면 결과를 보존하고 실제 장애를 보고한다. 성공한 척하거나 다른 시스템의 경로를 Mac 경로로 표현하지 않는다.

완료 답변에는 실제 ZIP의 전체 경로·핵심 결과·남은 항목을 짧게 적는다. PM은 그 ZIP을 ChatGPT에 첨부해 검토를 요청한다. 매번 저장 위치를 다시 묻지 않는다.

## 로컬에서 규칙 받기

이 규칙은 [AGENTS.md](https://github.com/Finn-02/MEMORIDE/blob/main/AGENTS.md)에 연결되어 있다. 기존 작업을 보존하면서 최신 main을 받은 뒤 AI가 AGENTS.md와 이 규칙을 다시 읽게 한다. 이미 진행 중인 Codex 세션에는 규칙을 명시적으로 다시 전달한다.

문서 반영은 실행 지침의 저장이며 Mac의 자동 작업 스케줄러나 완료 hooks 설치가 아니다. 각 로컬 작업에서 AI가 ZIP 생성·검증까지 수행한다. Git에는 검토 ZIP과 개인 경로가 담긴 로컬 보고서를 올리지 않는다.
