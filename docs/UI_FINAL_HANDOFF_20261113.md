# UI 최종 통합 전달 — 2026-11-13 KST

기존 통합 PR #29와 `part/a-a01-bootstrap`에 사용자 요청 UI 후속 변경을 정리한다. 기존 A03 실제 내비 연결 및 B·C·PM 통합 이력을 포함한 PR이며, 이 문서는 그 뒤의 UI 수정분에 대한 전달 기준이다. main 병합·최종 인수·Ready 전환을 수행하지 않는다.

## 최종 동작

- 캐릭터 선택·기본 섬·여정 대기·인벤토리·월드·첫 방문/재방문 결과의 Pleos 가로 UI를 정리했다. Asta Sans 본문, Jua 이름, Baloo2 로고와 로컬 Lucide 아이콘을 재사용한다.
- 내비 목적지 대기 화면의 완료 버튼은 `목적지에 도착했어요`이다. 실제 도착 선언은 별도의 플로팅 확인에서 진행한다. 예상 선물은 읽기 전용 안내이며 지급 성공이 아니다.
- 공통 모달은 흰 카드·전체 화면 어둡게/블러·짧은 확대/페이드 효과를 사용한다. 배경 탭으로 닫히지 않고 기존 `아직 아니에요`/도착/Back 경로를 사용한다. 처리 중 비활성·스피너·중복 입력 가드가 있다. 주소 입력이 없으면 숨긴다.
- 결과 화면은 저장된 영수증을 사용한다. 새 선물 3개를 한 행에 표시하고, 여정 기록 → 섬 성장 → 섬 복귀 순서와 선물 강조 표현을 정리했다. 좁은 창은 내부 스크롤을 사용한다.
- 인벤토리 캐릭터·섬 이름·닫기 배경은 흰색이다. 음식/의상 캐릭터 크기를 줄이고 HD 원본을 사용한다. 먹기 성공 시 이름을 바꾸는 대신 주변 반짝임을 표시한다.
- 장식은 1 왼쪽 / 2 뒤쪽 / 3 오른쪽 카드와 섬 위 표시로 위치를 고른다. 미리보기 중 번호만 스티커로 유지하며 `여기에 놓기`를 눌러야 기존 저장 콜백이 실행된다. 표시 위치는 실제 슬롯 PNG의 알파 범위에서 계산한다. 선택 상태는 UI에서만 유지한다.
- 기본 섬/장식 섬의 캐릭터를 확대하고 기존 발 위치를 유지했다. C 제공 이미지 45장을 교체하고 HD 프레임 36장을 추가했다. [출처/해시](C_INVENTORY_ART_CANDIDATE_20261113.md)를 참조한다. 대기 차량 일러스트는 [기존 생성 기록](JOURNEY_CAR_ASSET.md)을 따른다.
- 화면 진입에 220ms 페이드와 24dp 이동을 적용한다. 이전 화면을 살아 있는 상태로 겹쳐 보관하지 않는다. 확인 팝업의 배경은 움직이지 않으며 이용 제한/UNKNOWN 화면은 애니메이션 대기 없이 우선한다.
- 내비 복귀 시 새 캐릭터 선택을 반복하는 현상을 보완하기 위해 MainActivity를 재사용하고 SavedStateHandle에 외부 내비 복귀 상태만 복원한다. 일반 최초 진입의 캐릭터 선택은 유지한다. 실제 상태/제한/저장 결과를 복원값으로 만들지 않는다.
- 캐릭터 화면의 명시적 시연용 초기화와 debug 저장 QA/팝업 표본 진입점은 실제 게임 저장/플랫폼 제한 경계를 유지한다. debug 표본은 정식 실제 방문 검증이 아니다.

## 경계와 표시 자료

`io.kailand`, 콘텐츠 ID·저장 키·저장 schema와 B의 보상/원자 저장 서비스는 유지한다. 실제 gate/UNKNOWN, foreground·owner·generation, 원본 재시도·receipt ack가 우선한다. 새 유료 서비스·API 키·DO/overlay 권한·제한 우회는 추가하지 않았다. 공용 목적지 슬롯의 `destinationLabel`은 표시 전용 기본값 필드이며, A와 섬 소비자가 함께 반영된 상태다.

**여정 기록의 시연 표시 주의:** 현재 `ResultDemoOptions.USE_MOCK_TRIP_RECORDS = true`이다. 실제로 없는 수치는 명시적 시연 안내와 함께 화면에만 표본을 표시한다. 원본 영수증의 측정값 null은 유지되며 실제 주행 측정/방문 인증 근거로 사용하지 않는다.

## 검증 상태

사용자가 화면 확인을 담당하고 AI에는 코드 수정만 요청했다. 따라서 **이번 최종 HEAD의 `check_all.py --android`, 단위 시험, APK 빌드, 앱/에뮬레이터 실행과 화면 검수는 NOT RUN**이다. 새 내비 복귀 회귀 시험 5개도 작성만 했고 실행하지 않았다.

이전 중간 소스에서는 Windows Python 66개, Android/JUnit 386개와 debug 빌드가 통과한 기록이 있다. 당시 팝업 UI 표본 검수도 수행했지만, 이후 아트/HD 로더/장식 위치/캐릭터 크기/내비 복귀/전환 효과 변경을 포함한 최종 소스의 검증 근거가 아니다. 최종 테스트 개수나 PASS를 추정하지 않는다.

PR 준비 시 Git 변경 범위와 전달 이미지 해시를 확인했다. 변경 텍스트는 저장소 LF/UTF-8 기준으로 정리한다. Git 검토는 Android/SDK/실차 시험이 아니다. Actions 워크플로는 파일상 수동 전용이며 실행하지 않는다. 저장소 설정상의 비활성화/비용 상태는 별도 확인 대상이다.

## main 반영 전 남은 확인

1. A의 기록된 JBR/커밋 wrapper로 최종 HEAD의 정적·단위·debug 빌드를 확인하고 정확한 SHA/결과를 보충한다.
2. 내비 출발 → 목적지 입력 → 앱 복귀 → 여정 대기, 실제 제한/UNKNOWN 우선, 저장/실패 재시도/중복 입력/ack를 확인한다.
3. UI 크기·글자·가로/좁은 창·HD 표정/의상·장식 스티커/교체 미리보기를 사용자/담당자가 확인한다.
4. PM의 최종 통합 확인 뒤 Create a merge commit으로 병합하고 파트 브랜치를 유지한다. 이번 작업에서는 자동 병합/Ready 전환을 하지 않는다.
