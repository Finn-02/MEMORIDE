# 12 Codex와 Claude의 효율적인 활용

## 12 1 참고한 저장소 방식

agentsmd/agents.md의 AGENTS.md, vercel/next.js의 canary AGENTS.md 앞부분, anthropics/claude-code의 CLAUDE.md를 실제로 확인했다. 공통 지침을 예측 가능한 파일에 두고, 저장소 구조·실행 명령·변경 범위·검증 방법을 구체적으로 쓰며, 작업과 관련된 부분만 읽게 하는 방식을 가져왔다. 대형 프로젝트의 웹 빌드 명령·전용 runner·복잡한 자동화는 복사하지 않는다. [S18, S19, S20]

OpenAI의 Codex 지침과 Anthropic의 Claude Code 문서는 작업 범위를 좁히고 프로젝트 규칙을 관리하는 근거로 사용한다. 큰 지침 파일 하나에 모든 것을 집어넣지 않는다. 이 패키지의 AGENTS.md는 짧은 공통 기준과 찾아갈 문서 목록을 제공하고, 역할별 세부 계약은 roles와 docs에 둔다. CLAUDE.md는 @AGENTS.md만 가져와 두 도구의 규칙이 엇갈리지 않게 한다. [S21, S22]

## 12 2 한 작업의 입력 단위

하나의 AI 작업은 담당 폴더 안에서 끝낼 수 있는 1~3시간 분량의 결과로 잘라 시작한다. 이 시간은 계획 가이드다. “카일랜드 전체를 구현해” 대신 “ArrivalReceipt로 브리핑 5가지 상태를 표시하고 닫기 콜백을 연결해”처럼 완료 조건이 분명해야 한다.

입력에는 목표, 수정 허용 경로, 읽어야 할 계약, 재현 데이터, 완료 기준, 실행할 검증만 넣는다. 전체 DOCX·모든 PDF·전체 채팅을 매번 붙이지 않는다. ZIP은 전달용이며, 압축을 푼 뒤 필요한 MD와 코드만 읽게 한다. 스크린샷을 반복 전송하기보다 화면 ID와 달라진 상태를 지정한다.

## 12 3 작업 절차

먼저 AI가 git status와 관련 규칙·파일을 확인하게 한다. 5줄 안팎의 작은 계획 뒤 구현하고 관련 검증을 실행한다. 결함이 명확하고 담당 범위 안이면 PM 확인 없이 고친다. 공용 계약·비용·주행 제한·핵심 범위를 바꿔야 하면 변경 요청 템플릿으로 근거와 더 작은 대안을 적는다.

완료 답변은 바뀐 동작, 변경 파일, 수행한 시험·결과, 남은 한계, 다음 작업을 짧게 받는다. 실행하지 못한 시험은 통과라고 쓰지 않는다. 세션을 끝낼 때 docs/status의 자기 파일에 다음 사람이 이어갈 수 있는 짧은 상태를 남긴다. 대화 전체를 다시 읽는 비용을 줄이는 용도이며 장문의 일지를 쓰지 않는다.

## 12 4 중복 비용을 줄이는 운영

한 브랜치의 같은 파일을 Codex와 Claude가 동시에 수정하지 않는다. 한 도구가 구현하고 사람이 확인한 뒤, 데이터 손상·제한 처리·계약 변경 같은 위험 부분만 다른 도구로 검토한다. 단순 문구·아이콘·간격 변경을 두 모델에 모두 검토시키지 않는다. 사용량이 줄었다는 정량 수치는 측정 전 주장하지 않는다.

빌드 실패는 가장 먼저 나온 의미 있는 오류와 관련 설정·diff만 전달한다. 수천 줄 로그·빌드 산출물·캐시를 통째로 입력하지 않는다. 같은 시도가 두 번 실패하면 SDK 타입·버전·공식 예제를 직접 확인하고, 해결이 안 되면 작은 격리 실험 또는 DEMO 경로를 사용한다. 맹목적으로 생성과 재생성을 반복하지 않는다.

구독형 IDE·CLI 접근과 API 키 사용은 과금 체계가 같다고 가정하지 않는다. 현재 계정에서 이용 가능한 인증 방식을 확인하며, 이번 저장소에는 API 키·유료 AI Actions를 넣지 않는다. 사용량 한도에 도달하면 템플릿·정해진 계약·로컬 구현으로 이어가고 추가 구매를 필수로 만들지 않는다. 팀이 실제로 각자 접근할 수 있는 계정·기기 조건은 D1에 확인한다.

## 12 5 지침이 해서는 안 되는 일

AGENTS.md는 모델의 판단을 돕는 문서이지 접근 권한이나 오류 없는 실행을 보장하는 보안 장치가 아니다. 계정 설정·수동 검토·파일 소유권·검증이 함께 필요하다. 자동 push·자동 merge·대량 파일 삭제·비밀 출력·유료 의존성 추가를 편의상 허용하지 않는다. 다른 파트의 미완성 코드를 일괄 리팩터링하지 않는다.

규칙이 너무 길어 작업을 방해하면 담당자가 반복되는 문제를 근거로 줄일 수 있다. 새로운 규칙을 매 실패마다 계속 추가하지 말고, 구조·계약·검증으로 해결할 수 있는지 먼저 확인한다. AI가 모든 세부 작업을 PM에게 되묻도록 만들지 않는다.

## 12 6 착수 개정의 간단한 사용 방식

첫 요청에는 AGENTS, 자신의 roles 파일, 이번 작업 ID, 필요한 계약·샘플만 전달한다. ZIP 전체를 매 요청에 다시 첨부하지 않는다. 한 모델로 구현하고 다른 모델은 저장·동의·입력 경계처럼 위험한 변경의 짧은 리뷰에만 쓴다. 실제 토큰 절감률은 측정하지 않았으며 작업 범위를 줄이는 운영 원칙이다.

CLAUDE.md는 공통 AGENTS를 import하는 작은 호환 파일이다. 설치한 Claude Code 버전의 AGENTS 자동 로딩 지원 여부를 확인하고 같은 지침을 중복 유지하지 않는다. Codex도 작업 범위의 AGENTS와 관련 코드만 읽게 한다. 문서는 모델의 문맥이며 파일 접근을 강제 차단하는 보안 장치가 아니다. [S21, S22]

명령은 OS에 따라 python3 또는 py -3를 사용한다. AI가 수행하지 못한 Gradle·Pleos·Windows 시험은 NOT RUN으로 보고한다. 인터넷의 다른 기술 스택용 AGENTS를 통째로 복사하거나 추가 Actions·API 키·유료 서비스를 제안 없이 도입하지 않는다.
