# 개발 착수 확인

전체 설계를 다시 승인하는 절차가 아니다. PM과 A가 첫 날 확인하고 각자 작업을 시작한다.

- [ ] 컨셉 기준서 1.2와 MEMORIDE 표시명을 확인하고 파트 1·2·3 배정을 완료한다.
- [ ] A/B/C/PM 담당과 실제 가용 시간, 2:2:2:1 목표를 확인했다.
- [ ] private 저장소·part 브랜치·리뷰 짝·해당 저장소 Actions 우선 비활성을 정했다.
- [ ] A01 공통 앱·DTO·wrapper를 같은 루트에서 열고 첫 debug 빌드를 확인했다.
- [ ] config/toolchain.json과 ENVIRONMENT에 실제 버전을 기록했다.
- [ ] Mac과 Windows의 로컬 JDK·SDK 경로, 이미지 feed, 줄바꿈·파일명을 구분했다.
- [ ] B/C/PM은 샘플 입력으로 독립 시작하고 내부 함수는 자율 설계한다.
- [ ] 3일차 한 지역 통합·8일차 첫 release·내부 제출 여유를 확인했다.

SDK·주차 입력 시험은 D2까지 실제 결과를 적는다. 미완료 체크를 문서 배포만으로 완료 처리하지 않는다.
