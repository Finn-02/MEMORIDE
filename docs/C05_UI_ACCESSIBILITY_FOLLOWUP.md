이번 작업은 사용자 요청의 별도 UI 검사이며 고정 debug Vulkan 비교·서명 v4 최초 설치와 별개다.

## 시험 환경과 경계

새 빈 `MEMORIDE_C05_UI_ACCESS_API37` / emulator-5590 / user0 / 일반 API37 x86_64,
1080×2400/420dpi, Emulator37.2.13/build16740729, RAM4096, SwiftShader/Vulkan disabled,
cold boot/no snapshot으로 실행했다. 기존 AVD의 hardware 설정만 새 디렉터리로 옮겼고 userdata는 복사하지 않았다.
기존 C_COMPARE·서명 설치 AVD·게임 기록을 사용하거나 삭제하지 않았다.

현재 코드의 debug APK SHA256
`167d03f3fc6344bd46c27592252d66724a756d780a16b401c1be904493677147`.
기록된 JBR25.0.4/wrapper9.3.1의 `assembleDebug` exit0/7초/39개 UP-TO-DATE로 기존 유효 산출물을 재사용했다.
APK 최초 설치 Success, 공개 `DevelopmentActivity` 실행 후 UI의 ‘A04 실제 저장 화면 확인’을 눌러 진입했다.
내부 `DevelopmentGameActivity`를 ADB로 직접 시작하지 않았다. 이 debug용 일반 Android DEMO gate는
정식 Main의 실제 주차 허용 또는 Release/Pleos/안전 인수가 아니다.

초기 부팅 중 ADB offline으로 최초 install/start 명령이 실패했다. QEMU는 생존했고
59.923초 부팅 완료 뒤 설치·공개 진입 Status ok/COLD(3.614초)를 확인했다.
부팅 로그의 ColorBuffer 오류를 숨기지 않지만, 성공한 UI 관찰을 앱 종료로 분류하지 않는다.

상단 가로 메뉴는 손가락 드래그로 끝의 방문 버튼에 접근했다. 첫 드래그에서 사용자 확인 모드가 선택됐고,
후속 동행 검사 전에 DEMO를 명시적으로 선택했다. 이를 mode 전환 없는 UI 검사로 표현하지 않는다.
회전 도구의 첫 UIA 입력은 창 경계 밖 오류로 실행되지 않았다. 새 도구 스크린샷의 좌표로 회전하고
전환 애니메이션이 끝난 뒤 결과를 관찰했다. 초기 font 복원 drag는 실제2.0이 유지돼 복원 성공으로 세지 않았고,
이후 UI의 기본 단계 선택 및 실제1.0을 확인했다.

## 게임 데이터와 범위

새 환경에서 방문 요청·화면 이탈·모드/설정·동행 표시만 검사했다. 모의 여정은 출발까지만 진행했고
도착/보상/초기화는 누르지 않았다. 방문 뒤와 최종 `run-as` 읽기에서 datastore 폴더가 없음을 확인했다.
읽기 명령의 파일 없음 오류를 저장 해시 보존 PASS로 표시하지 않는다. 게임 진행/보상 생성이 관찰되지 않았다는 범위다.
원본 영수증·보유/외형 저장 복원은 기존 별도 인수 근거이며 이번 새 환경에서 재실행하지 않았다.

이번 관찰 중 반복 가능한 앱 기능 결함은 확정하지 않았으므로 소스·공통 계약·다른 파트 코드를 수정하지 않았다.
가로·2배 글자에서 상단 고정 영역으로 본문이 작고 스크롤이 많이 필요한 한계는 남는다.
