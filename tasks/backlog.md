# 작은 작업과 전달 순서

작업 ID는 대화와 PR에서 재사용한다. 아래 순서는 권장 WBS이며 내부 함수 설계는 담당자 자율이다. 포인트 총합은 A20 B20 C20 PM10이다. SDK 불확실성과 UI 물량의 실제 차이는 D3·D7에 재평가한다. 작업이 크면 PR을 더 작게 쪼개되 새 관리 문서를 늘리지 않는다.

PM의 범위·일정·자료·접수 관리는 위 10포인트 밖이다. A가 app 파일에 연결하는 동안 다른 사람은 동일 AppRoot를 동시에 수정하지 않는다. 각 담당자는 자기 공개 함수의 연결 예제를 PR에 적고 A는 해당 예제를 조립한다. 연결이 한 번 맞은 뒤 내부 수정마다 A에게 새 요청을 보내지 않는다.

필수 경로는 A01 → A02와 B02와 P01 → A04 → 첫 release → 전체 인수다. C02는 이 경로와 병렬로 개발 가능하다. B04가 늦어도 C01은 임시 슬롯으로 진행한다. SDK 탐색은 A03에 시간 상한을 두며 다른 필수 경로를 계속 진행한다. 기술 활용성의 실제 증거가 부족해지는 한계는 제출 문서에 남긴다.

파트 번호는 1=A, 2=B, 3=C다. 이름과 버전 변경으로 작업 점수를 늘리지 않았다. U19·U20·I06은 기존 저장·초기화·브리핑 작업의 확인 항목이다.
