# 파트 3 동행과 방문 및 여정 체험

목표는 심사위원이 이동 동행과 동의 기반 방문을 직접 바꿔보며 이해하도록 만드는 것이다. 실제 지도 API·GPS 이동·두 차량·통신 서버는 필요하지 않다.

## 읽을 것

AGENTS, docs/03·05·07·09·15·16, contracts/ui_contracts.md, fixtures, tasks/backlog의 C01~05.

## 작업 순서와 산출물

1. C01: 도형 지도·여정 텍스트·고정 캐릭터 영역의 모의 내비 화면을 만든다. B가 없으면 회색 슬롯을 쓴다. 화면과 수치는 DEMO로 표시하고 지도·안내 위젯을 캐릭터가 덮지 않게 한다.
2. C02: 한 프로세스의 가상 발신 A·수신 B와 VisitController를 만든다. 목적 표시, 수락·거절·만료·철회·닫기를 구현한다. 만료는 monotonic clock, 시험은 fake clock이다.
3. C03: GameSnapshot과 Catalog만 읽는 월드맵·지역 상세·수집 목록을 만든다. 아이템 지급·저장은 실행하지 않는다.
4. C04: JourneyPort로 목적지, DemoControlPort로 출발·완료·취소·마지막 도착 반복을 요청하는 수동 패널을 만든다. fixture UUID로 A의 ID를 덮어쓰지 않는다. UI 샘플을 live 저장에 넣지 않는다.
5. C05: 방문의 늦은 수락·동시 요청·쿨다운·화면 이탈·전체 초기화를 시험한다. C의 Windows PC를 APK 설치와 시연 백업으로 준비한다.

## 다른 파트와의 연결

입력은 A의 여정·gate, B의 읽기 상태, PM의 시나리오 파일이다. B의 외형은 AppRoot의 avatarSlot으로 전달된다. 방문은 로컬 일시 상태이며 영구 게임 저장과 분리한다. 초기화 요청은 A에게 전달하고 게임 상태를 직접 지우지 않는다.

## 최소 검증과 완료

U07~08, S08~09를 우선한다. 수락 전·거절·만료·이전 requestId의 늦은 수락에서는 방문이 없어야 한다. 제한·화면 이탈·모드 전환에서 방문과 예약 타이머를 취소한다. 실제 차량 제한을 모의 주행 버튼으로 바꾸지 않는다. D03 직후 D04는 같은 도착을 반복하고 새 지급은 없어야 한다.

## 막힐 때

자동 재생·화려한 걸음·월드맵 확대 기능을 빼고 수동 다음 버튼과 정적 카드로 줄인다. 수락·거절과 source 구분은 유지한다. 계약을 바꾸지 않는 화면 변경은 PM 승인 없이 진행한다.


작업 ID의 C는 기존 명세의 식별자다. 파트 선택·경계·충돌 예시는 docs/PART_GUIDE.md와 docs/18_final_review.md를 참고한다.

1.2 추가 확인: I06의 지역 선택과 U20의 Runner 중단. 새로운 관리 절차가 아니라 해당 기능의 기존 시험에 함께 포함한다.

## 시작 안내와 자율 설계

[환경 설치](../docs/ONBOARDING.md)와 [AI 설정](../docs/LOCAL_AI_SETUP.md)을 마친 뒤 [이 역할의 첫 작업·시작 프롬프트](../docs/FIRST_TASKS.md#part-3)로 진행한다. 세부 작업 분해·내부 코드·UI 설계는 담당자가 자기 AI와 자율적으로 결정한다. 기존 계약 안의 내부 계획과 일반 결함마다 PM 승인을 요청하지 않는다. A01 공통 앱을 받은 뒤 같은 빌드 파일을 사용하며 별도 Android 앱을 만들지 않는다.
