# 공식 기획서에 옮길 내용

2026-11-01 공식 접수양식 본문을 확인한 작성 안내다. 공식 파일 자체를 대체하지 않는다. 운영용 참가 정보와 심사용 작품 소개를 구분하고, 심사용 장에는 개발자 실명·소속·연락처를 기재하지 않는다. 팀원 동의·서명·날짜와 CC는 별도로 확인한다. 현재 프로젝트명은 임시다.

1. 한 줄 소개: 일상 이동과 지역 여행이 나만의 캐릭터와 섬의 성장으로 이어지는 차량용 라이프 게임.
2. 기획 배경: 가족의 출발 전·도착 후 짧은 공동 경험, 반복되는 출퇴근의 작은 즐거움, 지역 발견에 대한 관심을 목표 고객과 연결한다. 실제 수요 조사 결과가 없으면 가설이라고 쓴다.
3. 주요 기능과 차량 특화: 정차 중 섬·꾸미기, 여정에 따른 일상 성장과 지역 선물, 캐릭터 동행 컨셉, 동의 기반 가상 방문. 실제 SDK 연동과 모의 화면의 범위를 분리한다.
4. 사용 시나리오: 캐릭터 선택 → 목적지·여정 설정 → 동행 모의 장면 → 도착 결과 저장·브리핑 → 기념품 사용 → 가상 방문 수락·거절. 주행 장면은 이번 프로토타입의 주차 상태 시뮬레이션임을 표시한다.
5. 개발 계획: Kotlin Compose 단일 앱, NaviHelper 목적지 요청·조회와 검증된 도착 입력, 실제 제한 우선, 로컬 DataStore, DEMO 어댑터, 가상 차량 A/B. 구현 후에는 실제 확인한 버전·호출·기록만 기재한다.
6. 기대효과와 발전: 이동의 개인화·가족 경험·지역 콘텐츠 관심을 제안한다. MAU·리텐션·갈등 감소를 실적처럼 만들지 않는다. 필요하면 예상치의 가정과 측정 계획을 구분한다.
7. 참고자료: 같은 버전의 화면·시연 영상·private GitHub 소스와 release APK 위치·실행 README. 내부 개인정보가 있는 명세서를 그대로 첨부하지 않는다.
8. 숏폼: 선택 참여이며 본상 가산점과 구분한다. 제작하면 공식 길이·방향·해시태그 조건을 확인하고 링크를 기재한다.
