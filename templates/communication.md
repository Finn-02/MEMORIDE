# 짧은 파트 간 소통

공유 계약이 유지되는 내부 작업에는 요청 문서를 만들지 않는다. 요청은 한 번에 필요한 정보만 보내고 상대 답을 기다리는 동안 현재 계약의 샘플로 계속한다. 같은 내용을 채팅·Issue·문서에 세 번 복사하지 않고 Issue 또는 PR 하나를 기준으로 링크한다.

## 일반 요청

```text
[요청 ID/작업 ID] 받는 사람:
필요한 변경과 이유: 현재 → 원하는 동작
영향 계약/파일과 필요한 시점:
그동안 진행할 대안:
완료 확인: 입력 → 기대 결과
```

예: C04 → A, D04 재시연에 기존 도착 ID 유지가 필요함. RepeatLastArrival 사용 시점을 확인해 달라. 현재는 중복 버튼만 비활성화하고 방문·월드맵 개발을 계속함. 완료 확인은 D03 직후 반복에서 새 보상 0이다.

## 결함 보고

```text
[BUG/작업 ID] 담당 후보:
환경: OS/CPU/JDK/AVD/SHA
재현: 1. 2. 3.
기대/실제:
핵심 오류 5~15줄 또는 화면 1장:
영향과 우회:
```

## 큰 그림 변경만 PM에게

```text
[범위 변경] 바꿔야 하는 기존 합의:
이유와 확인한 증거:
가장 작은 대안/일정·비용·데이터 영향:
결정 전 계속할 작업:
```

무응답은 깨지는 변경의 승인이 아니다. 기존 계약으로 진행한다. 막힌 작업만 분리하고 전체 파트를 멈추지 않는다. 일상 질문은 같은 작업 스레드에 짧게 답하면 되고 별도 회의록은 필요 없다.

## AI에 줄 작은 작업

```text
역할/작업 ID:
AGENTS와 roles/<담당>.md 및 관련 계약을 먼저 읽어라.
이번 목표와 수정 가능한 경로:
입력/기대 행동/완료 조건:
현재 SHA와 필요한 파일:
검증 명령:
범위 밖 변경은 제안만 하며, 실행 결과와 미실행을 구분해 보고하라.
```
